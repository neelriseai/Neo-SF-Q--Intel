# Graph-grounded specialist proposal foundation review

## Scope

This review covers the isolated A5 graph-grounded specialist proposal/verifier boundary. It does not
claim a production OpenAI/Azure adapter, hard cancellation, workflow consumption, tool execution,
fact promotion, release authority or adjudicated answer quality. The governance release interlock
remains unchanged.

## Independent challenge result

The first implementation was rejected. The genericity lane demonstrated forgeable replay callbacks,
caller-root substitution, invalid ontology signatures, reversed/misbound citations, duplicate and
conflict bypasses, provider timing gaps and a superficial scenario-invariance claim. The governance
lane demonstrated persisted credential canaries, paired outcome substitution, provider-controlled
receipt metadata, incomplete budget enforcement and unsupported evaluation claims. Two remediation
passes replaced these boundaries, and a final Salesforce session-token canary was added before both
lanes approved the slice.

## Implemented boundary

Every public build, execute and verify path directly replays retained original A3/A4 inputs against
internally pinned repository policy, evaluation and ontology roots. The provider-neutral contract
owns a hash-bound profile and captured outcome; host-measured time, usage and stable failure codes
are verified. Provider JSON is strict and bounded, all source text is untrusted data, common
credential/session formats and absolute paths are rejected, and no raw exception is persisted.
Relation proposals must match ontology endpoint signatures plus the cited path's order and relation.
Candidate propositions are evidence/entity bound, duplicate hypotheses fail, unresolved fusion
conflicts force abstention, and every artifact remains analysis-only, candidate/inferred and unable
to authorize or satisfy release evidence. Persisted artifacts replay against an independent full
provider-outcome capture digest.

## Truthful foundation gaps

The capability remains `FOUNDATION`. A trusted composition root must supply the real provider
adapter; that adapter must use strict structured output, disable tools, apply network cancellation
and attest the configured profile. A6 must consume the proposal only after replay and must preserve
all deterministic facts and the `INCOMPLETE` release posture. The checked-in evaluation manifest is
`NOT_RUN` with zero invariant passes and zero of twenty adjudicated quality cases; repository tests
and this review ledger are the current execution evidence, not a semantic-quality claim.

Regenerate the project index and application graph, then run the complete Python, genericity,
governance, TypeScript, Playwright and Next.js gate before commit. The user-owned old discussion
