# Frozen three-hour agentic live vertical

## Authority and objective

This is the frozen execution boundary resumed by explicit user instruction on 2026-09-11. It
supersedes any interpretation of the stop-checkpoint resume list as a deterministic-only target.
Do not broaden, narrow or substitute this boundary without a new explicit user decision recorded
in this document and the requirement registry.

The objective is one reusable, source-neutral Neo run that joins real model reasoning, deterministic
assurance, the enrolled non-production Salesforce org and Playwright browser evidence in one
traceable vertical. Finishing more offline foundations does not satisfy this objective.

## Mandatory evidence chain

The same immutable run/trace must bind, in order:

1. the complete current local-Git candidate and verified source/graph identities;
2. a deterministic, project- and snapshot-isolated `GraphContextPack`;
3. at least one actual OpenAI specialist invocation through the provider-neutral interface;
4. a strict typed proposal containing only claims and citations supported by that context pack;
5. deterministic schema, citation, policy, freshness and authority validation, with abstention on
   unsupported, ambiguous, malformed, stale or unavailable evidence;
6. source-derived impact and test obligations used by the bounded live campaign rather than a
   hardcoded demo route, selector, object, field, record or test name;
7. the applicable live Salesforce baseline, candidate/check-only, deployed-candidate, browser and
   restoration gates in `config/live-salesforce-acceptance-profile.json`;
8. headless Playwright assertions and locator-recovery evidence against the deployed candidate;
9. exact metadata restoration, zero scoped residue and final reconciliation; and
10. durable sanitized model, graph, PostgreSQL, Salesforce, Playwright and test artifacts indexed
    under the same source/build/policy/campaign roots.

OpenAI is the active development provider. The same provider contract must remain configurable for
Azure OpenAI on the org machine; provider-specific values stay in environment configuration. A
provider readiness check, fake provider, fixture response or deterministic substitute is not an LLM
invocation and earns no agentic acceptance.

## Binary completion definition

The three-hour target is complete only when all of the following are true:

- at least one real model-backed specialist invocation is accepted with 100% valid cited evidence,
  zero unsupported citations and a schema-valid typed deliverable;
- deterministic validation demonstrably rejects malformed output, unsupported citations and
  provider failure without relabelling fallback output as model reasoning;
- all applicable live profile gates have current accepted receipts for the same run/campaign;
- the headless browser suite verifies the candidate and correctly reports any healed locator;
- Salesforce metadata is restored exactly with zero scoped residue and no unknown remote job;
- PostgreSQL persistence/replay and every required regression gate pass; and
- Astra reports no unresolved P0 or scope-contradicting P1.

If any condition is absent, status remains `INCOMPLETE` with the exact blocker. Passing deterministic
tests, reaching Salesforce diagnostically, rendering the dashboard, or recording an LLM response in
isolation cannot be used as a substitute.

## Explicit exclusions

New connectors, Chroma implementation, broader Salesforce applications, additional demo scenarios,
unrelated UI polish, production-org use and additional metadata mutation types remain outside this
timebox. These exclusions reduce breadth only; they do not weaken the mandatory vertical above.
